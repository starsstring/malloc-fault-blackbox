# 故障现场黑匣子

这是 malloc 作业的完整 C 案例。普通采样只更新固定环形缓冲区；异常发生时，申请一块独立内存，复制截至触发时的最近若干帧。继续采样时，旧快照仍保持不变。

代码是标准 C11 用户态程序，不依赖 GPIO、传感器、内核模块或开发板型号。温度均为模拟数据。
当前验证环境是 Windows x64 / TinyCC 0.9.27，共 31 项行为检查通过；Linux、鲁班猫及 sanitizer 尚未实测。

## Linux 或鲁班猫运行

执行位置：普通 Linux 终端或已登录鲁班猫的 SSH 终端。先把本目录复制到设备个人目录，再进入 `blackbox_demo`。
编译和运行只在当前目录生成程序、打印数据，无需 sudo，不修改系统配置。编译报错时停止，保留首条错误。

```sh
cc -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror blackbox.c -o blackbox
./blackbox --budget 256
```

若系统没有 `cc` 但有 `gcc`，将 `cc` 替换为 `gcc`。Windows 的 exe 不能直接作为 ARM Linux 程序使用。

```sh
./blackbox --budget 128
./blackbox --budget 256 --fail-after 1
```

前一条展示预算不足，后一条展示申请失败。两者预期均以非零状态退出，表示存在未能保存的事件；程序仍会输出并释放已有快照。
正常路径使用 `--budget 256`，保存全部四个事件，退出状态为零。

已有 make 和 Python 3 时可以运行 `make test`。可选的 `make sanitize` 需要平台支持 AddressSanitizer 和 UndefinedBehaviorSanitizer，当前未执行该项验证。

## 运行内容

模拟温度为 `25,42,27,28,29,46,26,27,49,26,51,25` °C。
默认 40 °C 触发一次事件，发生在第 2、6、9、11 帧。默认窗口为 4 帧，包含触发帧以及最多 3 帧历史。

| 触发帧 | 快照内的序号 | 后续覆盖后仍保留 |
| --- | --- | --- |
| 2 | 1、2 | 是 |
| 6 | 3、4、5、6 | 是 |
| 9 | 6、7、8、9 | 是 |
| 11 | 8、9、10、11 | 预算足够且分配成功时 |

程序最后打印实时环形缓冲区 `9,10,11,12`，再打印历史快照，便于直接比较。
这里的“黑匣子”仅为功能类比：快照只在进程 RAM 中存在，程序退出后不保留，不具备断电保护或真实故障恢复功能。

## 参数

| 参数 | 默认 | 范围和含义 |
| --- | --- | --- |
| `--window N` | 4 | 1..16，快照上下文帧数上限，包含触发帧 |
| `--budget N` | 128 | 1..8192，快照请求字节数的合计上限 |
| `--samples N` | 12 | 1..12，仅处理输入序列的前 N 帧 |
| `--threshold N` | 40 | 1..100，模拟温度触发阈值，单位 °C |
| `--fail-after N` | 不注入 | 0..4096，N 次成功后模拟 malloc 返回 NULL |
| `--help` | 无 | 参数帮助 |

最多同时保存 8 份快照。每个达到阈值的采样帧独立触发一次事件，没有实现迟滞、去抖或异常恢复识别。
阈值仅用于可重复的教学实验，不是实际设备的安全阈值。

## malloc 的作用

`Snapshot` 使用柔性数组成员，将头部和实际帧数据放在一次申请中：

```c
typedef struct {
    size_t event;
    size_t count;
    Sample frames[];
} Snapshot;
```

申请 `sizeof(Snapshot) + count * sizeof(Sample)`，检查上溢、预算和 NULL 后再复制数据。
预算使用减法比较，避免 `used + bytes` 上溢。每份快照由记录器拥有，结束时每块只调用一次 `free`。
故障注入只是模拟失败，不会故意耗尽机器内存。

本机 `sizeof(Sample)=8`、`sizeof(Snapshot)=16`，第一个事件请求 32 B，其余各 48 B。
预算 128 B 时保留前三份，预算 256 B 时保留四份。目标平台的大小以程序 CONFIG 行为准。
预算只约束快照申请大小，不含分配器开销、固定缓冲区、栈、C 库和进程 RSS。

## 设计取舍

平时只覆盖固定空间，异常时保留独立快照，体现实时数据与事件数据的不同生命周期。
申请失败时放弃当前事件，保留历史事件并继续处理后续输入。达到预算后也采用拒绝新事件的策略，没有静默覆盖历史快照。

快照申请、复制、打印仍发生在同一线程。本程序不保证硬实时；严格时序系统应进一步将事件处理移到后台任务，使用预分配的快照池。
环形缓冲区和快照是已有方法，本例的辨识度来自嵌入式故障上下文、单块变长快照、预算约束及故障注入的具体组合，不宣称算法首创。
